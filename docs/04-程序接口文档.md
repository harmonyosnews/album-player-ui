## 1. 通用约定

### 1.1 Base URL

```
http://<player-host>:7778
```

- 播放器 Web 界面端口：**7778**（官方安装指南 [E10]）。
- 渲染器 `ap2renderer` 端口：**7779**，不属于本文范围。
- 新 UI 与 aplayer **同源**部署，前端使用相对 URL：
  - `/?GetAlbums`
  - `/SetConfig`
  - `/stop`

### 1.2 认证 / 会话

- **无认证、无 Cookie、无 Token、无会话。**
- 任何能访问 7778 的客户端都可以控制播放、读取配置、浏览文件系统。
- 部署范围限可信 LAN；远程访问必须加代理/鉴权/VPN（二期）。

### 1.3 HTTP 特性（实测）

| 项 | 值 |
|---|---|
| HTTP 版本 | HTTP/1.1 |
| `Server` | `APlayer Web Server` |
| `Connection` | `close`（无 keep-alive） |
| JSON `Content-Type` | `application/json;Charset=UTF-8` |
| HTML `Content-Type` | `text/html` |
| JS `Content-Type` | `text/javascript` |
| CSS `Content-Type` | `text/css` |
| PNG `Content-Type` | `image/png`（`GetImage` 会重复发送两次） |
| CORS | 无 `Access-Control-Allow-Origin`；`OPTIONS` 返回 **501** |
| 未知命令 | HTTP **404** + HTML `Command Not Found` |
| 未知静态文件 | HTTP **404** + HTML `File Not Found` |
| 路径穿越 | `../` 被拒绝（404） |

### 1.4 请求方式

- 绝大多数命令是 **GET + 查询串**：`GET /?Command&param=value`。
- 配置写入是 **POST /SetConfig**，JSON body。
- 添加电台是 **POST /?AddStation**，JSON body。
- 命令名大小写敏感（`GetAlbums` ≠ `getalbums`）。
- 参数值需要 URL 编码（尤其是播放列表名、电台名、URL）。

### 1.5 响应类型

| 类型 | 示例 | 说明 |
|---|---|---|
| JSON 对象 | `{"Result":"OK"}` | 大多数命令 |
| JSON 数组字段 | `{"Albums":[...]}` | 列表类 |
| 纯文本 | `Settings saved!` / `Player stopped!` | 配置/退出 |
| 二进制 | PNG/JPEG | `GetImage` |
| HTML 404 | `<HTML>...` | 未知命令/文件 |
| 空响应/连接重置 | `HTTP=000` | aplayer 退出/音频设备不可用（非正常契约） |

### 1.6 超时与重试

- 建议客户端超时 **5 s**（`GetImage` 可 10 s）。
- 只读 GET 可重试 2 次（指数退避）；**命令不要自动重试**（避免重复播放/删除）。
- aplayer `Connection: close`，每秒轮询会新建 TCP 连接；LAN 下可接受。
- 同一时间只发一个命令；不要并发 `SetConfig`、`Play`、`Delete*`。

### 1.7 安全注意

- 所有字符串按不可信内容处理（专辑名、曲目名、电台名、列表名、`conv_list`）。
- `Playlists` 数组元素可能包含 HTML；不要直接 `innerHTML`。
- 电台 URL 只允许 `http:`/`https:`。
- 不要向前端暴露 `api_key`/`api_cx`。
- 配置写入前备份；`SetConfig` 是整包覆盖。

### 3.3 `POST /SetConfig`

保存完整配置。

**请求**

```http
POST /SetConfig HTTP/1.1
Host: ARM-BUILD-HOST:7778
Content-Type: application/json; charset=utf-8

{"covers":"Covers;","pframes":128,"bframes":2048,...}
```

**响应（实测）**

```
Settings saved!
```

- 不是 JSON；厂商 UI 设置了 `dataType:'json'` 但忽略解析结果。
- 失败时可能返回 `Settings not saved!`（前端字符串推断）。
- **整包覆盖**：请求体里没有的字段会回到默认值。实测只提交 `{"covers":"Covers;"}` 后，`config.dat` 从 668 B 变成 900 B，其他字段被默认化 [E6]。
- **必须**先 `GET ?GetConfig`，合并完整可写字段，再 POST。
- 保存后再次 `GET ?GetConfig` 校验。
- 写入前备份 `config.dat`；实测会话后该文件也可能被回写（触发点未完全隔离），按最保守假设备份。

| `Albums` | string[] | 专辑显示名（可能与 `AlbumList` 不同；电台模式含后缀） |
| `AlbumList` | string[] | 专辑名（信息展示用） |
| `AuthorList` | string[] | 艺术家，与专辑索引对齐 |
| `YearList` | string[] | 年份，与专辑索引对齐 |
| `Songs` | object[] | **当前专辑**的曲目块（实测通常只有 1 个元素；不要假设与全部专辑索引对齐） |
| `Songs[0].SongsLen` | int[] | 当前专辑每首曲目时长（ms） |
| `Playlists` | string[] | 播放列表/目录显示名，**可能含 HTML** |
| `SavedAlbumIndex` | int | 上次选中的专辑索引 |
| `SavedSongIndex` | int | 上次选中的曲目索引 |
| `RadioMode` | bool | 当前是否电台模式 |

**注意**

- `Playlists` 不是“用户播放列表”的纯文本；它是目录/列表浏览数据，元素含 HTML 图标。展示前必须 `htmlToText`。
- 空库时 `Playlists` 会返回根目录列表（实测），这是 aplayer 的文件系统浏览行为；新 UI 默认不展示 `/`。
- `Albums`/`AlbumList`/`AuthorList`/`YearList` 的索引对齐；`Songs` 只对应**当前专辑**（实测 4 张专辑时 `Songs` 仍只有 1 个元素）。
- 每张专辑的曲目必须用 `GetSongs&album=N` 单独读取；不要用 `Songs[N]` 取第 N 张专辑。
- 电台模式下同一结构语义变为“分类/电台”：`AlbumList` 是干净的分类名，`Songs[0]` 是第一个分类的电台列表；每个分类用 `GetSongs` 读取。
- 载入目录/列表后，建议重新 `GetAlbums`；`GetAlbums` 的 `SavedAlbumIndex`/`SavedSongIndex` 可用于恢复上次选择。

### 4.2 `GET /?GetSongs&album=N`

读取某专辑曲目。

**请求**

```http
GET /?GetSongs&album=0 HTTP/1.1
```

**响应（有效）**

```json
{"Songs": ["曲目 1", "曲目 2"], "SongsLen": [180000, 240000]}
```

**响应（无效/空）**

```json
{}
```

- `N` 为 `GetAlbums` 的专辑索引，0 起。
- 实测 `album=999` 返回 `{}`（HTTP 200）。
- `Songs` 为曲目名数组；`SongsLen` 为对应时长（ms），可直接用于列表显示。
- `GetAlbums.Songs` 只包含当前专辑；其它专辑必须逐张 `GetSongs`。
- 大库建议懒加载：先 `GetAlbums` 拿列表，进入详情再 `GetSongs`。

### 4.3 `GET /?GetImage&pl=N&image=M&time=T`

读取专辑封面。

**请求**

```http
GET /?GetImage&pl=0&image=0&time=1690000000000 HTTP/1.1
```

| 参数 | 说明 |
|---|---|
| `pl` | 播放列表索引（厂商 UI 用 `PlaylistIndex`，默认 0） |
| `image` | 专辑索引（0 起） |
| `time` | 缓存破坏时间戳（毫秒） |

**响应（实测）**

```http
HTTP/1.1 200 OK
Server: APlayer Web Server
Connection: close
Content-Type: application/json;Charset=UTF-8
Content-Type: image/png
Content-Length: 4768
```

- 返回 PNG/JPEG 字节；样本为 296×205 PNG（默认 logo）。
- **重复 `Content-Type`**：先 JSON 后 image；浏览器 `<img>` 通常能正常显示，但严格客户端应注意。
- 失败/无封面可能返回默认图；不要假设一定是专辑封面。

### 4.4 `GET /?GetPlaylists&ind=N`

读取播放列表/目录树。

**请求**

```http
GET /?GetPlaylists&ind=-1 HTTP/1.1
```

**响应结构**

```json
{
  "Playlists": [
    "aplayer.dat",
    "<span style='color:rgb(255,255,144)'>&#8862; </span>armbian",
    "&nbsp;&nbsp;&nbsp;&nbsp;images"
  ],
  "Drives": [
    {"path": "", "name": "aplayer.dat", "level": 0, "expanded": 0},
    {"path": "/armbian", "name": "armbian", "level": 0, "expanded": 0},
    {"path": "/bin", "name": "bin", "level": 0, "expanded": 0}
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `Playlists` | string[] | 显示列表（含 HTML 图标/缩进） |
| `Drives` | object[] | 目录树：`path`、`name`、`level`、`expanded` |

**`ind` 语义（实测/推断）**

- `ind=-1`：根列表（实测）。
- `ind=0`：根列表（实测，与 -1 类似）。
- `ind=1`：**切换**第 1 个条目的展开/折叠（实测；已展开时再调用会折叠，不是单纯展开）。
- `ind=N`：切换对应条目（推断）。
- 越界/无效 `ind` 可能返回空/异常；前端应使用 `Drives` 的索引并在范围内请求。
- `Drives[].expanded`：0 未展开、1 已展开、2 子项/其它状态；UI 用 `expanded === 1` 判断显示“折叠/展开”。
- `GetPlaylists&ind=-1` 会受上一次展开状态影响，可能直接返回已展开的树。

**注意**

- 这是 aplayer 的文件系统浏览接口；会暴露根目录。新 UI 默认只展示 `root_folder` 下的内容。
- `Playlists` 含 HTML，展示前清理。
- `Drives` 是更结构化的数据，优先用它渲染树。

### 4.5 `GET /?GetPlaylist&playlist=N` / `?Get_Playlist&playlist=N`

加载第 N 个播放列表/目录，使其成为**当前播放列表**，之后 `GetAlbums` 才返回该列表的专辑视图。

**请求**

```http
GET /?GetPlaylist&playlist=0 HTTP/1.1
```

**响应（实测）**

```json
{"Result": "OK"}
```

- 两个命令在厂商 UI 中都被使用，行为看起来一致；`Get_Playlist` 可能是旧别名。
- `playlist=N` 的 N 与 `GetPlaylists` 返回的 `Drives` 索引对齐（实测 `Drives[1]=music` 时 `playlist=1` 载入成功）。
- 成功只返回 `Result`；专辑/曲目需要随后 `GetAlbums`/`GetSongs` 刷新。
- 载入子目录（如 `/opt/aplayer/music/Aurora Sessions`）会让 `GetAlbums` 只显示该目录的专辑（实测 1 张）。
- 无效索引实测仍返回 `{"Result":"OK"}`，需结合后续状态判断。

### 4.6 `GET /?Play&album=N&song=M`

播放指定专辑/曲目。

**请求**

```http
GET /?Play&album=0&song=0 HTTP/1.1
```

**响应（成功推断）**

```json
{"Result": "OK"}
```

**响应（实测错误）**

```json

```

- `album`/`song` 索引来自 `GetAlbums`/`GetSongs`。

- 失败原因可能是文件不存在、格式不支持、音频设备不可用。
- 调用后轮询 `State`，不要仅凭 `Result` 判断已开始播放。

### 4.7 播放控制

| 接口 | 响应 | 说明 |
|---|---|---|
| `GET /?Stop` | `{"Result":"OK"}`（实测） | 停止 |
| `GET /?Pause` | `{"Result":...}`（前端） | 暂停/继续（切换） |
| `GET /?Next` | `{"Result":...}`（前端） | 下一首 |

- 所有命令后刷新 `State`；不要乐观更新为“已播放”。

### 5.1 `GET /?RadioMode`

切换/查询电台模式。厂商 UI 点击电台按钮时调用，随后用 `GetAlbums` 重新渲染。

**响应（实测）**：与 `GetAlbums` 相同结构，`RadioMode` 字段反映切换后状态。

### 7.1 `GET /?SelectCard&card=N`

**请求**

## 8. 错误与异常

### 8.1 HTTP 状态

| 状态 | 场景 | 响应 |
|---|---|---|
| 200 | 正常/业务错误 | JSON/文本/图片 |
| 404 | 未知命令 | HTML `<H1>Command Not Found</H1>` |
| 404 | 未知文件 | HTML `<H1>File Not Found</H1>` |
| 501 | `OPTIONS` 预检 | HTML（无 CORS 头） |
| 000/连接重置 | aplayer 退出/音频设备不可用 | 无 HTTP 响应 |

### 8.2 业务错误

- `{"Result":"Can't play file"}`：播放失败（实测）。
- `{"Result":"OK"}`：成功。
- `{"Result":"..."}`：其他错误字符串；展示前消毒。
- `{}`：空结果（如 `GetSongs` 无效专辑、`GetPictures` 空）。
- `GetConfig` 的 `LastError`：最近一次错误，可能为空。

### 8.3 客户端处理建议

```ts
if (res.status === 404) -> "接口/文件不存在，可能 aplayer 版本不匹配"
if (!res.ok) -> "播放器返回 HTTP xxx"
if (JSON.parse 失败) -> "响应格式异常"
if (Result && Result !== 'OK') -> Toast(Result)
if (fetch 抛错) -> 离线横幅 + 退避
```

### 8.4 已知怪癖

1. `GetImage` 重复 `Content-Type`（JSON + image）。
2. `Connection: close`，无 keep-alive。
3. `Playlists` 元素含 HTML。
4. `SetConfig` 整包覆盖；部分提交会重置。
5. `SelectCard` 可能停止播放/重配音频。
6. aplayer 会话后 `config.dat` 可能被回写（触发点未完全隔离）。
7. 无 PCM 设备时操作音频相关命令可能导致进程退出。
8. `OPTIONS` 501，无 CORS。
9. 无效 `GetPlaylist` 仍返回 OK（需结合状态判断）。
10. `GetPlaylists` 暴露文件系统。
11. `GetAlbums.Songs` 只含当前专辑，不是全库曲目表。
12. `GetPlaylists&ind` 是展开/折叠**切换**，不是单向展开。
13. `GetAlbums` 是当前播放列表视图；不先 `GetPlaylist` 可能为空。
14. 电台 `SongsLen` 是约 10 小时的占位值，不是真实时长。

### 9.4 错误类型

```ts
export type ApiErrorCode =
  | 'NETWORK' | 'NOT_FOUND' | 'HTTP_4XX' | 'HTTP_5XX'
```

- `NETWORK`：离线横幅/退避。

## Part C：可选伴生服务 API（二期）

> MVP 不实现。仅当需要鉴权/SSE/配置事务/多机聚合时启用。前端 SPA 可复用，API 基址切到 `/api`。

### 10.1 设计目标

- 监听 `0.0.0.0:7780`，内嵌 SPA。
- 代理 aplayer `7778`，参数校验，限制文件系统浏览。
- 可选 Basic Auth/Token；CSRF/Origin 检查。
- `GET /api/events` SSE：轮询 aplayer `?State`，变化时推送。
- 配置事务：备份/合并/校验/恢复。

### 10.2 端点草案

| 方法 | 路径 | 说明 |

### 10.3 SSE 事件格式

```
event: status
data: {"playing":true,"paused":false,"album":0,"song":2,"positionMs":12345,"durationMs":234000,"volume":80,"title":"...","formatText":"FLAC 96kHz/24bit/2ch"}

event: radio
data: {"radioTitle":"...","pics":["..."]}

event: error
data: {"code":"APLAYER_OFFLINE","message":"..."}
```

- 心跳 15s（注释行 `: ping`）。
- 客户端断线重连；服务端轮询 1s，变化才推。
- 不做音频数据流；只推状态。
