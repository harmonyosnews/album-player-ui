## 4. aplayer HTTP 实测（E4/E11）

### 4.1 启动方式（隔离副本 + 恢复）

```bash
# 在 .230
rm -rf /tmp/ap-probe && mkdir -p /tmp/ap-probe
cp -a /opt/aplayer/. /tmp/ap-probe/
cd /tmp/ap-probe
nohup ./aplayer > /tmp/ap-probe.log 2>&1 &
sleep 5
ss -lntp | grep 7778
```

> 注意：即使从 `/tmp/ap-probe` 启动，aplayer 仍会切换到 `/opt/aplayer`（`/proc/<pid>/cwd -> /opt/aplayer`，`exe -> /opt/aplayer/aplayer`）。因此所有配置读写都作用于 `/opt/aplayer`；必须备份/恢复。

## 6. 配置写入行为与恢复（E6）

### 6.1 部分提交会重置配置

```text
POST /SetConfig
Content-Type: application/json
{"covers":"Covers;"}

响应：Settings saved!
```

结果：

```text
/srv/.../config.dat  668 B  ->  900 B
md5 before af0c46ae1ddd481a7eea3864d886ca21
md5 after  df56091d4bcc5cfe6c41833ade2aa48d
```

> 结论：`SetConfig` 是整包覆盖；未提交字段回落默认。新 UI 必须提交完整可写字段。

### 6.2 会话后配置会被改写（触发点未完全隔离）

- 在一次包含启动、GET 查询、`?Stop`、`?SetVolume`、`?State`、`/stop` 的会话后，`config.dat` 从 668 B 变为 900 B。我们没有把触发点隔离到单一动作（启动/退出、`Stop`/`SetVolume`、配置保存都可能）；因此按最保守假设：任何测试会话都可能回写。
- `aplayer.log` 会追加启动/停止记录。
- 因此所有测试/部署脚本必须备份并恢复；本文档的恢复操作：

```bash
# 用启动前抓取的原始副本恢复
cp /tmp/config.dat.orig /opt/aplayer/config.dat
chmod 600 /opt/aplayer/config.dat
touch -d '2021-09-04 02:29:19' /opt/aplayer/config.dat
cp /tmp/aplayer.log.orig /opt/aplayer/aplayer.log
chmod 644 /opt/aplayer/aplayer.log
touch -d '2026-10-11 18:55:22' /opt/aplayer/aplayer.log
```

恢复后：

```text
md5sum /opt/aplayer/config.dat
af0c46ae1ddd481a7eea3864d886ca21  /opt/aplayer/config.dat

-rw------- 1 root root 668 2021-09-04 02:29:19 /opt/aplayer/config.dat
-rw-r--r-- 1 root root 107 2026-10-11 18:55:22 /opt/aplayer/aplayer.log
```

- 临时探针文件/进程已清理；7778 空闲。
- 原始 `config.dat` 已通过本地 `work/230/opt/aplayer/config.dat` 复核哈希 `af0c46...`。
