## 1. 方案目标与边界

### 1.1 目标

交付一套可直接替换 aplayer 内置 Web 界面的新前端，满足：

- 同源运行在 `http://<播放器>:7778/`，不新增端口/服务。
- 覆盖 aplayer 2.19 的核心操作：专辑/艺术家/曲目浏览、播放/暂停/停止/上下曲/进度/音量、网络电台、播放列表、常用设置。
- 视觉与交互达到 tinylms 1.3.4 的水准：深色主题、卡片、底部播放条、全屏正在播放、移动端适配。
- 一份静态产物同时用于 ARM64（`.230`）与 x86_64（`.137`）。
- 可安装、可卸载、可回滚；不破坏 aplayer 配置与音频链路。

### 1.2 不做

- 不改 aplayer 二进制、不反编译、不改音频/ALSA/Diretta/DSD 处理。
- 不实现队列编辑、历史、歌曲收藏、歌词、标签、智能推荐、多房间。
- 不改 7779 端口的 UPnP 渲染器界面。
- 不在 `.133` 做真实听感/DSD/声卡验收。

### 1.3 关键成功指标

| 指标 | 目标 |
|---|---|
| 核心操作覆盖 | 播放/暂停/停止/上下曲/进度/音量/专辑/电台/列表/设置 = 100% |
| 首屏加载 | 局域网 < 2 s（冷启动） |
| 构建体积 | JS < 300 KB gzip，CSS < 80 KB gzip |
| 空闲请求 | 1 次/秒 `?State`，页面隐藏时降频 |
| 稳定性 | `.137` 播放/待机无前端崩溃、无配置损坏 |
| 兼容性 | Chrome/Edge/Firefox/Safari 最近两个大版本；iOS/Android |
| 可回滚 | 卸载后 1 min 内恢复厂商 UI |
| 安全 | 无 XSS；不显示敏感配置；危险操作二次确认 |

## 2. 总体方案

### 2.1 架构（MVP）

```
┌──────────────────────────────────────────────────────────────┐
│ 浏览器（桌面/平板/手机）                                      │
│   http://<player>:7778/  →  aplayer.html → ui/app-<hash>.js   │
│                                    └────→ ui/app-<hash>.css  │
└───────────────────────────┬──────────────────────────────────┘
                            │ 同源 fetch（无 CORS）
┌───────────────────────────▼──────────────────────────────────┐
│ aplayer 进程（2.19，7778）                                    │
│  静态文件：aplayer.html / ui/*                                │
│  JSON API：/?GetAlbums /?State /?Play /?SetConfig ...         │
│  音频：ALSA / Diretta / DSD（不变）                            │
└──────────────────────────────────────────────────────────────┘
```

- **没有新增进程、端口、反向代理、数据库。**
- 前端只做“读状态 + 发命令 + 写配置”，不做音频处理。
- 所有请求同源，直接复用 aplayer 的查询串 API。
- 部署 = 替换 `/opt/aplayer/aplayer.html` + 新增 `/opt/aplayer/ui/`。

### 2.2 为什么不用独立服务（MVP）

| 约束 | 原位静态替换 | 独立服务 |
|---|---|---|
| `.137` 无 systemd，OpenRC/supervise | 无需适配 | 需要写 OpenRC/supervise 单元 |
| aplayer 无 CORS，`OPTIONS` 501 | 同源直接调用 | 必须反向代理 |
| 低资源/低干扰 | 零常驻进程 | 多一个进程 + 轮询 |
| 端口/防火墙 | 不变 | 新增 7780 |
| 交付周期 | 短 | 长 |
| 鉴权/SSE/审计 | 无 | 有 |

结论：MVP 用原位静态替换；二期若需要鉴权/SSE/远程访问，再把同一套 SPA 的 API 基址切到伴生服务。

### 2.3 前端技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript 5.x | 类型约束接口字段，降低误用 |
| 构建 | Vite 7.x | 快速、输出可控、易做单包构建 |
| 框架 | **无框架（原生 TS + 模块 + 轻量 store）** | 与 tinylms 的 vanilla 架构一致；包体最小；无框架升级负担 |
| 样式 | 原生 CSS + CSS 变量 | 直接复用 tinylms 设计令牌；无预处理器依赖 |
| 路由 | Hash 路由（`#/albums`） | aplayer 静态服务器不会做 SPA fallback；hash 刷新不 404 |
| 图标 | 内联 SVG（TS 函数/字符串） | `.svg` 静态文件 404；内联不受白名单限制 |
| 字体 | 系统字体栈 | `.woff/.woff2/.ttf` 均 404 |
| 图片 | API 封面 + PNG 占位/CSS 渐变 | `.webp/.svg` 404；PNG 可服务 |
| 测试 | Vitest + Playwright（可选） | 单测解析/配置；E2E 走 mock/实机 |
| Lint | ESLint + Prettier + Stylelint（可选） | 统一风格 |
| 包管理 | npm（`.133` 自带）；pnpm 可选 | 无额外依赖 |

### 2.4 构建产物约束（必须写进 CI）

aplayer 静态服务器只接受以下扩展名（实测）[E5]：

```
允许：.html  .js  .css  .json  .png（以及既有 UI 使用的图片类型）
禁止：.svg  .woff  .woff2  .ttf  .webp  .mjs  .map  .txt
```

因此：

- Vite 输出**单个 JS + 单个 CSS**；关闭 code splitting、关闭 sourcemap。
- 所有 SVG 图标内联为字符串或 data URI；不生成 `.svg` 文件。
- 所有字体使用系统字体；如必须用自定义字体，转 base64 内联到 CSS（不推荐，体积大）。
- 占位图用 CSS 渐变或 PNG；不使用 WebP/SVG 文件。
- 构建后运行 `scripts/check-dist.mjs`，发现禁止扩展名直接失败。
- 入口文件命名为 `aplayer.html`；资源放 `ui/`，使用内容哈希文件名（`app-<hash>.js`）。

## 5. 关键实现设计

### 5.1 应用壳

- 桌面：`aside 260px` + `main` + `footer 128px`；内容区滚动，播放条固定。
- 平板：sidebar 折叠为图标/抽屉；内容两列。
- 手机：隐藏 sidebar；底部 `mobile-nav` 4 项（首页/专辑/电台/设置）；播放条 72px；点击封面/标题打开全屏正在播放。
- 顶栏：搜索、刷新、主题切换、全屏。
- 右侧详情栏（可选）：专辑/艺术家详情，桌面 >=1024 显示，移动端改为独立视图/底部抽屉。

### 5.2 路由

```
#/home
#/albums
#/albums/:index
#/artists
#/artists/:name
#/browse?path=...
#/radio
#/playlists
#/settings
#/settings → 关于（原 #/about 兼容跳转）
```

- 使用 hash，避免 aplayer 对未知路径返回 404。
- 路由参数只做展示；真正的专辑索引用 `GetAlbums` 快照解析，不跨库持久化。
- 刷新时重新拉取 `GetAlbums`，按“专辑名+艺术家”定位，而不是持久化索引。

### 5.3 API 客户端

```ts
// 伪代码
const base = import.meta.env.DEV ? '/ap' : ''; // 生产同源；开发走 Vite 代理
async function cmd<T>(query: string, init?: RequestInit): Promise<T> {
  const res = await fetch(`${base}/?${query}`, {
    cache: 'no-store',
    signal: AbortSignal.timeout(5000),
    ...init,
  });
  if (res.status === 404) throw new ApiError('NOT_FOUND', await res.text());
  if (!res.ok) throw new ApiError('HTTP_' + res.status, await res.text());
  const text = await res.text();
  try { return JSON.parse(text) as T; } catch { throw new ApiError('BAD_JSON', text); }
}
```

- 所有请求串行化（同一时间只发一个状态/命令），避免 aplayer 并发问题。
- 命令后立即触发一次 `State` 刷新；不要只依赖 1s 轮询。
- 失败分类：网络错误/HTTP 错误/JSON 解析错误/业务 `Result` 错误。
- 超时 5s；重试只用于只读 GET（最多 2 次，指数退避），命令不自动重试（避免重复播放/删除）。

### 5.4 状态轮询

```ts
// 伪代码
let timer: number | null = null;
let failures = 0;
function schedule() {
  const delay = document.hidden ? 5000 : (failures ? Math.min(8000, 1000 * 2 ** failures) : 1000);
  timer = window.setTimeout(tick, delay);
}
async function tick() {
  try {
    const s = await api.getState();
    failures = 0;
    store.setPlayer(s);
    setOnline(true);
  } catch (e) {
    failures = Math.min(failures + 1, 3);
    setOnline(false);
  } finally { schedule(); }
}
document.addEventListener('visibilitychange', () => { if (!document.hidden) { clearTimeout(timer!); tick(); } });
```

- `document.hidden` 时 5s；离线时退避 1/2/4/8s，最大 8s。
- 命令后 `refreshNow()`。
- 不在轮询里做重渲染整页；只更新播放条/当前视图的相关节点。

### 5.5 配置安全

**硬规则：`SetConfig` 必须提交完整可写字段，不能只提交修改项。**

流程：

```
1. 启动/进入设置页：GET ?GetConfig → cfg（完整快照）
2. 用户修改表单 → patch
3. payload = 从 cfg 提取“可写字段白名单”，覆盖 patch
4. 前端校验：类型/范围/枚举/必填
5. localStorage 保存上一版 cfg；提供“导出 JSON”
6. POST /SetConfig（完整 payload）
7. GET ?GetConfig → verify；对比关键字段
8. 失败/不一致：提示；提供“恢复上一版”（再次 POST 上一版）
```

可写字段白名单以厂商 `SaveConfig()` 的字段集为准（见接口文档 §5.3）。不要提交：

- `stat_*`、`ascii`、`cards`、`asound`、`catdate`、`exists_conv`、`conv_list`、`conv_desc`、`api_key`、`api_cx`。
- 未知字段（避免版本差异导致副作用）。

安装/升级前由脚本备份：

```
/opt/aplayer/config.dat → /var/lib/apui/backups/config-YYYYmmdd-HHMMSS.dat
```

由于 UI 不能写系统文件，脚本备份是运维层职责；UI 内提供 JSON 导出/导入作为用户级备份。

### 5.6 危险操作

| 操作 | 风险 | 交互 |
|---|---|---|
| `SetConfig` | 配置重置/音频异常 | 保存前确认；高级项折叠；保存后校验 |
| `SelectCard` | 停止播放、重新配置 ALSA | 二次确认；提示“会中断播放” |
| `DeletePlaylist` | 删除用户列表 | 二次确认；显示名称 |
| `DeleteAlbum` | 删除专辑条目（可能影响库） | 二次确认；默认隐藏 |
| `DeleteStation` | 删除电台 | 二次确认 |
| `Update0/1` | 联网更新/替换 Radio 目录 | 二次确认；提示先备份 `Radio/` |
| `?Stop` | 停止播放 | 普通按钮，无需确认 |
| `/stop` | 退出 aplayer 进程 | 不在 UI 提供；仅运维脚本 |

### 5.7 文件浏览边界

- `GetPlaylists&ind=-1` 会列出根目录 [E4]；这对普通用户是危险/困惑的。
- 新 UI 默认只显示 `GetConfig.root_folder` 下的内容；如果根目录为空，文件浏览页显示“未配置音乐根目录”，不展示 `/`。
- `Drives` 的树形数据由 aplayer 返回；前端按 `path` 前缀过滤，非根目录项隐藏。
- 不提供删除文件、重命名、上传；只允许“加载/播放”。
- 这是 UX 层过滤，不是安全边界；文档明确“可信 LAN”。

### 5.8 XSS 与 HTML 字符串

aplayer 的 `Playlists` 数组元素包含 HTML（如 `<span style=...>&#8862; </span>armbian`），`conv_list`/`conv_desc` 也可能含 HTML [E4]。新 UI：

- 所有来自 aplayer 的字符串先 `stripHtml` + `decodeEntities`，再 `textContent` 写入。
- 禁止 `innerHTML = albumName`、`insertAdjacentHTML` 拼接不可信数据。
- 图标用固定白名单的 SVG 字符串；不把用户数据插入 SVG。
- URL 字段（电台流、图片）只允许 `http:`/`https:`；拒绝 `javascript:`/`data:`（图片 data URI 仅用于内置占位）。
- 如果必须展示 `conv_list` 的富文本，用白名单 sanitizer（如 DOMPurify）或按纯文本显示。

### 5.9 电台

- 进入电台视图：`?RadioMode` 切换（注意这是全局模式，切换后 `GetAlbums` 的语义变为电台分类/条目）。
- 列表：`GetAlbums` + `GetSongs`（与专辑同构）。
- 正在播放标题：`GetRadio` 的 `RadioTitle`；每 10s 或状态变化时刷新。
- 图片：`GetPictures` 的 `Pics[]`；轮播间隔 `Config.num_pics`/20s；加载失败用占位。
- 收藏：`?Favor`；收藏目录 `Radio/!Favorites`。
- 添加：`POST ?AddStation`，body `{url,name,folder}`；folder 为分类名。
- 删除：`?DeleteStation&album=&song=`；删除前确认。
- 目录更新：`?Update0`（Update）/`?Update1`（Replace）；提示联网与备份。

### 5.10 设置页信息架构

### 6.1 构建（在 `.133`）

```bash
export PATH=/opt/node22/bin:$PATH

npm run build          # Vite → dist/

```

```
    app-<hash>.js
    app-<hash>.css
    i18n-<hash>.json      # 可选

```

### 6.2 安装（`.230` / `.137`）

`install.sh` 伪代码：

```bash
#!/bin/sh
set -eu
ROOT=/opt/aplayer
STAMP=$(date +%Y%m%d-%H%M%S)
BK=/opt/aplayer-ui-backup-$STAMP
[ -f "$ROOT/aplayer" ] || { echo "aplayer not found"; exit 1; }
mkdir -p "$BK"
cp -a "$ROOT/aplayer.html" "$ROOT/aplayer.js" "$ROOT/aplayer.css" "$BK/" 2>/dev/null || true
cp -a "$ROOT/config.dat" "$BK/" 2>/dev/null || true
mkdir -p "$ROOT/ui"
# 先写资源，最后原子替换入口
cp -a dist/ui/. "$ROOT/ui/"
cp -a dist/aplayer.html "$ROOT/aplayer.html.new"
mv "$ROOT/aplayer.html.new" "$ROOT/aplayer.html"
echo "installed; backup: $BK"
```

- 不停止 aplayer；静态文件替换不需要重启（实测热替换 `aplayer.html` 后 `GET /` 立即生效，API 不受影响）。
- 如果厂商 `aplayer.html` 引用 `aplayer.js/css`，新入口不再引用它们；保留备份以便回滚。
- 权限：`root:root 644`；`ui/` 目录 755。
- 不覆盖 `config.dat`、`Radio/`、`img/`（除非新 UI 需要新增 PNG；优先用内置 data URI）。
- 安装后验证：

```bash
curl -fsS http://127.0.0.1:7778/ | grep -q 'APUI' && echo OK
curl -fsS 'http://127.0.0.1:7778/?State' >/dev/null && echo API_OK
```

### 6.3 卸载/回滚

```bash
#!/bin/sh
set -eu
BK=${1:?usage: uninstall.sh /opt/aplayer-ui-backup-YYYY...}
cp -a "$BK/aplayer.html" /opt/aplayer/aplayer.html
# aplayer.js/css 如被覆盖也恢复
[ -f "$BK/aplayer.js" ] && cp -a "$BK/aplayer.js" /opt/aplayer/aplayer.js
[ -f "$BK/aplayer.css" ] && cp -a "$BK/aplayer.css" /opt/aplayer/aplayer.css
rm -rf /opt/aplayer/ui
echo "restored"
```

- 回滚不需要重启 aplayer；浏览器强制刷新（Ctrl/Cmd+Shift+R）。
- 如果新 UI 版本升级失败，保留上一个 `ui/` 目录或重新安装上一个包。

### 6.4 厂商升级后的重放

aplayer 升级可能覆盖 `aplayer.html/js/css`，但不会删除 `ui/`。运维步骤：

1. 备份新 `config.dat`。
2. 重新运行 `install.sh`（保留 `ui/` 或替换为新版本）。
3. 跑冒烟：`/`、`?State`、`?GetAlbums`、`GetImage`。
4. 跑 UI 回归清单（播放/暂停/切歌/设置）。

建议在 `install.sh` 中打印 `aplayer` 版本/哈希，写入 `/opt/aplayer/ui/VERSION`，便于对账。

### 6.5 兼容 `.137` 的 OpenRC

- 原位静态替换**不需要**新增服务，因此不需要 OpenRC/supervise 单元。
- 如果 `.137` 的 aplayer 由 GentooPlayer 管理，确认其工作目录确实是 `/opt/aplayer`；`/opt/aplayer/aplayer.service` 文件存在但系统无 systemd，说明启动由 GentooPlayer 自己的脚本/面板管理。
- 部署前在 `.137` 执行 `readlink /proc/$(pgrep -f /opt/aplayer/aplayer)/cwd` 确认 cwd；若 cwd 不是 `/opt/aplayer`，调整安装路径或服务的工作目录。
- 回滚同理，只替换文件，不触碰 init。

2. 备份 `/opt/aplayer`（至少 `config.dat`、`Radio/`、`aplayer.dat`）。

### 8.4 故障处理

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 页面 404/旧界面 | `aplayer.html` 未替换/被升级覆盖 | 检查文件；重跑 install |
| 页面加载但无数据 | aplayer 未运行/端口错误 | `ss -lntp \| grep 7778`；启动服务 |

| 移动端布局错乱 | 缓存旧 CSS/视口 | 强刷；检查 hash 资源 |

## 11. 二期可选：伴生适配服务（B 方案）

```
          ├─ 代理 → http://127.0.0.1:7778/?...
```
