1. 它是什么，不做什么

这份手册写给使用者，不要求你懂 aplayer 的 HTTP 接口或前端构建。它按“安装 → 怎么用 → 怎么确认正在播放 → 出问题先看哪里”的顺序组织。更深入的接口、构建和部署细节见 docs/04-程序接口文档.md 与 docs/03-开发手册.md。

使用前请阅读 APUI 用户协议与免责声明。APUI 只是控制界面：音量、DSD/DoP、声卡和功放状态仍由 aplayer 与你的音频设备决定。首次试听、切换格式或声卡时，请先把下游音量调到最低。

APUI（Album Player UI）是 Album Player for Linux 2.19 的一套独立 Web 操作界面。它是一组静态文件，安装时替换 /opt/aplayer/aplayer.html 并在 /opt/aplayer/ui/ 下放置 JS/CSS；之后仍由 aplayer 自己在 7778 端口提供页面。APUI 不新增系统服务、不新增端口、不改音频引擎，也不包含 aplayer 二进制。

它和厂商自带 UI 是“同一台播放器的两套遥控器”：两者都通过 aplayer 的本地 HTTP 接口读取曲库、发送播放命令、读写配置。切换 UI 不需要换播放器；卸载 APUI 就恢复厂商页面。

APUI 负责aplayer 负责
曲库浏览、封面、专辑/艺术家/曲目页面、搜索扫描媒体库、读取标签、封面与文件
播放/暂停/停止/上一首/下一首、进度、队列查看解码、缓冲、Gapless、DSD/DoP、ALSA/Diretta 输出
网络电台分类、播放、收藏、添加/删除入口电台目录、流连接、第三方图片/元数据
播放列表的保存、载入、删除界面播放列表文件（aplayer.dat/.ap2）的实际读写
设置表单、配置导入/导出、状态展示配置项的最终解释、声卡/DSD/音量行为
桌面/手机响应式布局、主题、全屏正在播放音频时钟、设备能力和播放结果

1.1 三个必须记住的边界

第一，APUI 没有登录。它和 aplayer 的接口一样，默认只适合可信局域网。不要把 7778 端口直接暴露到公网；远程访问请自行加 VPN、反向代理认证或防火墙。

第二，设置保存是“整包覆盖”。APUI 会把完整可写配置合并后提交；只改一个分页也会提交全部分页的当前值。改设置前请备份 config.dat，不要提交空白或来源不明的配置。

第三，APUI 不是官方组件。Album Player、TinyLMS 及其商标属于各自权利人。APUI 只提供前端，不改变 aplayer 的许可，也不代表厂商背书。

1.2 它不做什么

2. 安装与首次使用

APUI 1.0.0 的发布包是静态前端，不依赖 Node、Python 或额外的 Web 服务器。安装脚本会把入口文件热替换进现有 aplayer 目录，不需要重启 aplayer。

2.1 安装前确认

  • 目标机已经安装并运行 Album Player for Linux 2.19，7778 端口可访问。
  • 你有目标机的 root 权限；APUI 安装会写 /opt/aplayer。
  • 浏览器为现代 Chrome、Edge、Firefox 或 Safari；本项目主要在 Chromium 上验收。
  • 准备好同版本的发布包 apui-web-1.0.0.tar.gz 及其 .sha256。
# 在目标机先确认 aplayer Web 服务本身正常
curl -fsS http://127.0.0.1:7778/ | head

# 如果这一步失败，先不要安装 APUI；先让 aplayer 跑起来
systemctl status aplayer
# 或 OpenRC / GentooPlayer：
# rc-service aplayer status

2.2 安装

建议整个解包、进入目录、执行安装的过程都在同一个 root 会话里完成，避免文件属主和权限不一致。

sudo -i
cd /tmp
tar -xzf apui-web-1.0.0.tar.gz
cd apui-web-1.0.0
./install.sh /opt/aplayer

安装脚本会：

  • 把当前 aplayer.html、aplayer.js、aplayer.css、config.dat 和 ui/ 备份到 /opt/aplayer-ui-backup-<时间戳>/；
  • 把新的 ui/app-*.js、ui/app-*.css 放入 /opt/aplayer/ui/；
  • 原子替换 /opt/aplayer/aplayer.html；
  • 不重启、不停止 aplayer。

安装后先核对入口。浏览器打开 http://<播放器IP>:7778/，侧栏底部应显示 UI 1.0.0 · aplayer 2.19。如果仍显示旧版本，先强制刷新（Ctrl+F5 / Cmd+Shift+R），再检查 /opt/aplayer/aplayer.html 是否指向新的 ui/app-*.js。

2.3 配置音乐根目录

  1. 打开设置。点击右上角齿轮，不要点击浏览器菜单；进入“设置 → 常规”。
  2. 填写根目录。在“根目录”填写 aplayer 能访问的媒体库路径，不带首尾斜杠。例如 opt/aplayer/music 或 mnt/samba。
  3. 保存设置。点击页面底部“保存设置”，等待“设置已保存”提示。
  4. 刷新并回到首页。点击顶部刷新按钮，或点击左上角 Album Player 标志回首页。首页会自动载入根目录曲库。

APUI 1.0.0 不再把“上一次的当前播放列表”当成首页：初始化、回到首页时都会按根目录重新载入。根目录为空时，APUI 不会擅自载入系统 /，以免把系统目录当作媒体库。

2.4 升级、回滚与验证

升级时直接安装新版本发布包；安装脚本会重新生成备份。回滚使用安装包内的卸载脚本，把备份目录作为参数传入：

./uninstall.sh /opt/aplayer-ui-backup-<时间戳> /opt/aplayer

回滚同样不需要重启 aplayer；浏览器强刷即可。验证时至少检查三件事：

  • 页面能打开，侧栏版本号正确；
  • 首页能看到根目录曲库，不只是一张专辑；
  • 选中一张专辑能显示曲目，播放条有进度或明确的格式信息。

3. 五分钟出声

假设 APUI 已安装、根目录已配置。下面按最短路径完成一次本地播放；每一步都用同一个判据：播放条是否进入播放状态。

  1. 打开首页。地址是 http://<播放器IP>:7778/。左侧“首页”应显示当前/上次专辑，下面“全部专辑”显示根目录曲库。
  2. 选一张专辑。点击专辑卡片，打开专辑详情；确认曲目数量、标题和时长出现。
  3. 开始播放。点击“播放全部”或某一首曲目。播放条左侧应出现曲名和封面，中央按钮变成暂停图标。
  4. 确认真的在播。看进度时间是否前进、格式徽章是否出现（例如 44.1KHZ / 16BIT / 2CH）；不要只看按钮颜色。
  5. 打开队列。点击播放按钮右侧的队列图标，确认当前曲目在弹窗中高亮；按 Esc 或“取消”关闭。
  6. 停止或暂停。需要停下时点击播放条的暂停或停止；停止按钮在未播放时是灰色不可用的。

3.1 三个“没出声”先查的地方

先看正常表现不正常时
播放条暂停图标、进度时间前进、格式徽章按钮仍显示播放、时间停在 0：命令没有真正开始
设置 → 状态“正在播放”为“是”，播放文件非空检查 aplayer 输出设备、声卡与格式支持
音量与设备音量设置与功放/耳机状态正常APUI 不处理音频；检查 aplayer 配置与下游设备

听感风险：APUI 不提供额外的软件音量或限幅。切换 DSD/DoP、声卡或陌生电台前，请先关闭功放或把下游音量降到最低；确认格式与设备后再逐步开声。

4. 界面总览

APUI 的界面分四层：左侧导航、顶部工具栏、内容区和底部播放条。桌面和手机使用同一套状态，只是排布不同。

4.1 左侧导航

“发现”下有首页、专辑、艺术家、文件浏览；“我的音乐”下有网络电台、播放列表。这里没有“系统”或“关于”分栏：设置入口在右上角齿轮，关于内容在设置 → 关于。

4.2 顶部工具栏

控件作用
搜索框按专辑名、艺术家、年份过滤；在其他页面输入会自动跳到“专辑”。
齿轮进入设置。手机端也在右上角保留。
刷新重新读取当前曲库/播放状态；根目录或文件变化后使用。
太阳/月亮深色与浅色主题切换；偏好保存在本机浏览器。
全屏浏览器全屏；手机端一般隐藏。进入全屏正在播放请点击播放条封面或标题。

4.3 底部播放条

从左到右：封面与曲名（点击打开全屏正在播放）、上一首、停止、播放/暂停、下一首、当前播放队列、音量（仅当 aplayer 启用音量）。上方是进度条与左右时间。

  • 格式徽章来自 aplayer 状态，例如采样率/位深/声道/码率；DSD 可能显示较高的采样率。
  • 进度条在本地文件播放时前进；网络电台或 PlayingLen=0 时可能保持 0，这是接口特性，不一定是故障。
  • 音量滑块只在 aplayer 的 volume_enabled 开启时显示；没有滑块不代表播放失败。
  • 队列按钮在播放控制区最右侧，图标为三条横线加圆点；下一章专门讲。

全屏正在播放：点击播放条左侧封面或曲名打开，按顶部向下箭头或再次点击关闭。全屏页只放大展示正在播放的信息和控制，不改变音频链路。

5. 首页、专辑、艺术家与搜索

5.1 首页

首页顶部是“当前/上次专辑”Hero，适合继续上次的收听；下面“全部专辑”展示根目录曲库的全部专辑。点击卡片打开专辑，悬停卡片可以快速播放。Hero 的“播放”按钮会从该专辑第一首开始；如果它正是当前播放的专辑，则按钮变为暂停/继续。

5.2 专辑与曲目

  • “专辑”页展示完整网格，并按当前搜索词过滤；搜索只匹配专辑名、艺术家、年份等元数据，不搜索曲目内容。
  • 打开专辑后可以看到曲目列表、时长与当前曲目高亮；“播放全部”从第一首开始。
  • 封面来自 aplayer 的封面目录；没有封面时显示占位图，不影响播放。
  • APUI 不编辑标签、不改文件名；标签问题请在音乐文件或标签工具中处理。

5.3 艺术家

“艺术家”按 aplayer 的 AuthorList 聚合。点击艺术家进入其专辑列表，再打开具体专辑。没有艺术家头像时使用首字母/渐变占位；同一个艺术家名称的写法不同，会被视为不同条目。

5.4 搜索

搜索是浏览器端的即时过滤，适合在已经载入的曲库中快速找专辑。清空搜索框恢复全部结果。库很大时，第一次载入会花一些时间读取专辑和封面；如果页面一直为空，先看下一章的“首页没有专辑”。

6. 当前播放队列

队列视图只展示当前正在播放的专辑，不再把整个曲库的其他专辑列出来。它回答“这张专辑接下来放什么”，而不是复制一份完整媒体库。

6.1 打开与阅读

  1. 点击队列按钮。位置在播放条播放/下一首控制的右侧，图标像一份列表；全屏正在播放页也有同样的队列按钮。弹窗从下方出现。
  2. 看当前高亮。当前专辑有浅色背景，当前曲目左侧显示播放小三角；队列只包含这一张正在播放的专辑。
  3. 点曲目播放。点击队列中的曲目会立即播放并关闭弹窗；播放条与队列高亮同步。
  4. 底部操作。“保存播放列表”“清除队列”“取消”三个按钮样式一致；关闭也可用右上角 ×、点击遮罩或 Esc。

6.2 队列范围

队列内容随当前播放专辑变化。播放另一张专辑后，队列自动切换为新专辑；不会继续列出上一张专辑或整个曲库。这样可以避免把“播放历史”误当成“当前队列”。

底层仍然是 aplayer 的当前播放列表，但 APUI 只呈现当前专辑的曲目视图；切歌、暂停、继续不会清空当前专辑。

6.3 保存与清除

  • 保存播放列表：输入名称后调用 aplayer 的 SavePlaylist，保存当前 aplayer 播放列表为 .ap2；随后可在“播放列表”页看到。
  • 清除队列：停止当前播放并清空队列视图；不会删除音乐文件，也不会修改根目录曲库。再次播放专辑时会恢复为该专辑的队列。
  • 队列为空时，“保存播放列表”和“清除队列”会自动禁用；名称不能为空，不安全字符会被替换。

首页与队列的关系：回到首页会重新载入根目录曲库；播放中的专辑仍可继续。停止播放后再回到首页，APUI 会恢复根目录曲库视图。

限制：aplayer 没有队列重排/删除接口，APUI 不提供拖动排序；清除队列是停止播放并清空当前队列视图，不改动曲库文件。

7. 网络电台

点击左侧“网络电台”会直接进入电台模式，不需要再点“进入电台模式”。电台分类和本地专辑使用两套独立数据，不会把本地专辑混进电台页。

7.1 播放一个电台

  1. 在“分类”中点击一个分类，展开该分类下的电台列表。
  2. 点击电台条目开始播放；播放条显示电台标题或流名称，格式徽章可能显示码率。
  3. 正在播放时，可以点“收藏当前”保存到 aplayer 的电台收藏。
  4. 需要添加自定义电台时，点“添加电台”，填写名称、流地址和可选分类；需要删除时，在对应条目上执行删除并确认。
  5. 点“退出电台模式”，或点击左侧其他分栏，APUI 会自动退出电台并恢复本地模式。

7.2 电台页的边界

  • 电台目录来自 aplayer；分类/条目为空时，先在“设置 → 解码器 → 电台”检查目录日期，必要时更新目录。
  • 电台流可能没有总时长，进度条保持 0；右侧时间可能不推进，这是流媒体特性。
  • 电台图片、标题与流内容可能来自第三方，APUI 只做展示；请自行确认来源合法与网络安全。
  • 退出电台模式时如果正在播放本地音乐，aplayer 会按自己的状态恢复；不要依赖 APUI 保证“原曲从原位置继续”。

看不到分类或一直显示正在进入：先确认 aplayer 正在运行且网络可用，再点页面上的“重试”；仍失败时退出 APUI 页面重新打开，或在 aplayer 侧确认广播目录存在。电台目录更新会联网并修改本地目录，属于需要确认的操作。

8. 播放列表与文件浏览

这两个入口经常被混用：播放列表是 aplayer 保存的“歌单文件”，文件浏览是浏览服务器目录。前者用于收藏一组曲目，后者用于把某个目录载入当前列表。

8.1 播放列表

  • aplayer.dat 是 aplayer 最近一次使用的列表，通常保留为系统条目；APUI 不提供直接删除。
  • .ap2 是通过“保存当前”或队列弹窗“保存播放列表”生成的可载入列表，可以删除。
  • “载入”会把该列表设为 aplayer 当前播放列表，然后跳到“专辑”页显示其中内容。它不会复制音乐文件。
  • “保存当前”保存的是 aplayer 当前播放列表；如果当前列表是根库，就会保存整库。
  • 播放列表保存/删除后点击“刷新”，确认列表变化；操作失败时先检查 aplayer 目录权限。

8.2 文件浏览

“文件浏览”展示 aplayer 的 Drives 目录树。点击目录行可以展开/折叠；选择目录后载入，会把该目录下的音乐作为当前播放列表。展开/折叠是 aplayer 的切换语义，不是浏览器的树控件。

只载入你认识的目录。文件浏览能显示 aplayer 可访问的目录；误载系统目录会把无关文件当成媒体库。它也不会复制、移动或删除文件。载入前确认路径，并在设置里保留正确的音乐根目录作为首页来源。

9. 设置

设置页把 aplayer 的配置按官方习惯分成 7 个主分页，并中文化了常用字段。大多数默认值不需要动；只改你理解的项，并先备份配置。

9.3 保存、导入、导出的范围

这三个按钮都在设置页底部，作用范围是完整配置（全部可写字段），不是当前分页。状态和关于页是只读的，因此不显示“保存设置”，但仍可导出/导入配置。

  • 保存设置：先读取当前完整配置，合并表单改动，按可写字段白名单提交，再回读校验。成功会提示“设置已保存”。
  • 导出配置：下载当前完整配置的 JSON；出于安全考虑，不导出 api_key/api_cx 等敏感字段。
  • 导入配置：选择 JSON 文件后会明确确认；确认后只覆盖可写字段，不修改只读/敏感字段。导入前先备份 config.dat。

不要提交空白配置。aplayer 的保存接口是整包覆盖；只改一项也要保证其他字段是当前有效值。不要在配置未完整载入时刷新/重复提交，不要用来路不明的 JSON 覆盖生产设备。保存只代表配置写入成功，底层声卡/DSD 是否立即生效由 aplayer 决定；切换后请重新播放或按现场规范重启服务验证。

9.4 状态与关于

“状态”是只读页面：可以核对 aplayer 是否 root、进程优先级、16/24/32 bit 支持、原生 DSD、正在播放文件、输出和 ALSA 周期/缓冲。它适合在“没声音”时先判断是环境问题还是控制问题；“关于”展示版本、许可证、官方/仓库链接和 Credits，没有单独的 About 页面。

状态字段怎么读

字段含义 / 排查用途
Root 用户aplayer 进程是否以 root 运行；与现场部署方式有关，不是 APUI 的权限设置。
已用核心 / 优先级 / NiceCPU 亲和与调度；只在明确知道实时性需求时修改，改后对比播放稳定性。
支持 16/24/32 bit、原生 DSD设备能力摘要；“no”表示当前链路没有声明该能力，不代表文件一定不能转成 PCM 播放。
正在播放 / 播放文件最直接的“有没有开始播放”证据；文件为空时不要先怀疑进度条。
源 / 输出当前输入来源与输出后端；排查“有进度但没声音”时，先看输出是否为空/错误。
ALSA 周期 / 缓冲输出缓冲参数；与“常规”里的值对照，异常时恢复现场基线。

10. 手机与平板

手机端不是缩小的桌面：底部导航替代侧栏，播放条压缩，队列变成底部弹层，设置页会隐藏左侧分页导航并把表单改成单列。

10.1 布局与操作

  • 底部导航固定为首页、专辑、文件、电台；设置入口在右上角齿轮，艺术家/播放列表仍可通过桌面或其他入口访问。
  • 首页、专辑页的专辑网格在手机上是3 列；播放条在底部导航上方，队列按钮与上一曲/下一曲同风格。
  • 播放条控制组居中，播放/暂停图标位于圆形背景正中；进度条使用内容区全宽，保留左右时间。
  • 点击播放条封面/曲名打开全屏正在播放；英雄页进度条接近全宽，控制栏居中，退出按钮在左上角。
  • 设置页在窄屏下隐藏左侧分页导航，主分页以横向标签展示；开关行右对齐，文本输入占满一行。
  • 横屏/竖屏都可用；如果系统有安全区，底部导航会预留空间。

10.2 兼容性

本项目主要在 Chromium（桌面/Android）和移动视口模拟下验收；Firefox、Safari 和 iOS/Android 真机的逐项验收仍在后续清单中。遇到布局问题，先强制刷新、更新到 1.0.0，并提供浏览器与系统版本、截图和页面地址。

11. 常见问题

排障顺序：先确认页面能打开，再确认曲库/当前列表，再确认 aplayer 输出；不要把“音频设备问题”误判成 UI 问题。

现象先看什么常见原因与处理
页面打不开7778 是否监听；aplayer 是否运行；浏览器地址是否为根路径先让 aplayer 正常；不要访问 /?unknown 这类查询，aplayer 会返回 Command Not Found。检查防火墙/端口。
页面是旧版，或侧栏版本不对侧栏版本号；aplayer.html 引用的 ui/app-*.js强制刷新；确认安装脚本已替换入口；重新安装同版本发布包。
首页没有专辑设置 → 常规 → 根目录；文件浏览根目录为空/写法不对（不要首尾斜杠）；目录对 aplayer 不可见；保存后刷新。
首页只有一张专辑/上次的列表版本是否为 1.0.0；根目录是否配置1.0.0 会回到根目录；旧版请升级。根目录为空时不会猜库，需先配置。
点播放没声音播放条时间、格式；设置 → 状态；aplayer 日志APUI 只发命令；检查 aplayer 输出设备、音量、格式支持、另一台机器是否占用设备。
进度条一直是 0是否电台/流；ProgressVisible/PlayingLen流媒体没有总时长时正常；本地文件仍为 0 则查 aplayer 状态或格式。
音量滑块不见了设置 → 音量控制aplayer 未启用音量控制时按设计隐藏；不是 UI 缺失。
设置保存后没变化Toast 是否“已保存”；设置 → 状态确认保存的是完整配置；底层声卡/DSD 可能需要重新播放或按 aplayer 规范重启后生效。
设置保存失败错误提示；根目录/封面；config.dat 备份字段校验失败或 aplayer 无法写入；恢复备份后再改，逐项提交。
导入配置后不对导入确认框；JSON 来源；备份导入覆盖可写字段；用错文件就回滚 config.dat，不要在生产库上试未知配置。
电台分类为空/卡住网络；aplayer 电台目录；页面重试退出再进入；更新/替换目录需确认；检查 aplayer 的电台文件与网络。
队列里有其他专辑当前播放的专辑1.0.0 只显示当前专辑；点击播放新专辑后队列会切换。
保存播放列表失败名称为空？aplayer 目录权限/磁盘换名称；确认 aplayer 可写播放列表目录；保存的是当前列表，不是单曲。
手机布局溢出/按钮被挡浏览器缩放、横竖屏、版本强制刷新并升级 1.0.0；仍异常请提供设备、浏览器版本和截图。
升级 aplayer 后界面异常aplayer 版本；接口是否变化APUI 只适配 2.19 接口；升级前回归，必要时回滚 aplayer 或安装匹配版本。

如果问题只在某个浏览器/设备出现，先在另一个浏览器复现；只在一个浏览器出现时，优先检查缓存、扩展和缩放，而不是改 aplayer 配置。

12. 安全与运维纪律

12.1 网络边界

  • APUI 与 aplayer 的 HTTP 接口没有登录、没有权限分级；只应在可信局域网使用。
  • 不要把 7778 直接映射到公网，也不要在公开演示环境暴露真实媒体库。
  • 需要远程访问时，使用 VPN、带认证的反向代理和访问控制；APUI 本身不提供 TLS。
  • 浏览器端没有敏感账号，但配置、曲库名、电台和日志可能包含个人信息；截图/日志外发前先脱敏。

12.2 变更前备份

APUI 的设置保存会写 aplayer 的 config.dat；aplayer 也可能在运行、切换声卡或更新目录时改写配置/列表。修改前至少备份：

  • /opt/aplayer/config.dat（以及现场使用的其它配置）
  • /opt/aplayer/aplayer.dat、用户 .ap2 播放列表
  • /opt/aplayer/Radio/ 与电台目录（如使用）
  • APUI 的配置导出 JSON，以及必要的音乐元数据/封面

12.3 安装、升级与停止

  • 安装/回滚使用发布包内的 install.sh / uninstall.sh；安装脚本自带备份。
  • APUI 只替换静态文件，不控制 aplayer 进程；不要为了刷新页面而重启或强杀 aplayer。
  • 需要停止/重启 aplayer 时使用现场服务管理方式（例如 systemd 或 OpenRC 的正常 stop/restart）；不要使用 kill -9 处理音频进程。
  • 升级后核对侧栏版本和 aplayer.html 的资源名；回滚时使用对应时间戳的备份目录。

12.4 排障时的取证

# 页面入口是否正常
curl -fsS http://127.0.0.1:7778/ | head

# aplayer 当前状态（可直接看到 Playing/Album/Song/RadioMode）
curl -s 'http://127.0.0.1:7778/?State'

# aplayer 服务状态（按现场 init 系统选择）
systemctl status aplayer
# rc-service aplayer status

日志位置由 aplayer 决定；常见为 /opt/aplayer/aplayer.log。对外求助时请提供：APUI 版本、aplayer 版本、浏览器/系统、复现步骤、截图/控制台错误、?State 输出和最近日志的脱敏片段。
