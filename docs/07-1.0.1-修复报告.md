## 1. 问题与波次

按依赖关系分波修复，每波完成后再进入下一波，避免配置类型、扫描时序和目录索引互相掩盖。

### 波次 1：配置字段类型（Scream 桥 + CUE 开关）

**现象**

- 设置 → 声卡 → Scream 桥：勾选“启用/TCP”保存后，刷新又变成未勾选。
- WAV+CUE 专辑只显示/播放整轨 WAV，原版 UI 可以显示 ANSI CUE 分轨。

**根因（实测）**

aplayer `SetConfig` 对不同开关字段的类型要求不一致，类型不匹配时**静默存成相反值**：

| 字段 | 正确类型 | 发送错误类型的结果 |
|---|---|---|
| `ch_scr` / `ch_tcp` | `1` / `0` | `true` → 存成 `0` |
| `cue_mode` | `true` / `false` | `1` → 存成 `false` |

厂商 `aplayer.js SaveConfig()` 的写法也是 `ch_scr = ... ? 1 : 0`、`cue_mode = ... ? true : false`。APUI 1.0.0 对所有开关统一发送布尔值，且读取时只认 `=== true`，因此：

- Scream 勾选保存后被后端忽略；
- 若 `cue_mode` 被整包保存成数字 `1`，所有 WAV+CUE 专辑退化为整轨 WAV。

**修复**

- `web/src/api/config-fields.ts`
  - 新增 `BOOL_FIELDS` / `INT_BOOL_FIELDS` 与 `configBool()`；
  - `buildPayload()` 保存前按字段归一化：布尔字段写 `true/false`，整型布尔字段写 `1/0`。
- `web/src/views/settings.ts`
  - 开关显示改用 `configBool()`，兼容 `true/1/"1"`；
  - `ch_scr` / `ch_tcp` 改为 `intbool`。
- `web/src/store/index.ts`
  - 保存后校验新增 `cue_mode`、`tags_mode`、`ch_scr`、`ch_tcp`，类型归一化后比较。

**本地证据**

```text
SetConfig {"ch_scr": true, "ch_tcp": true} → GetConfig {"ch_scr": false, "ch_tcp": 0}
SetConfig {"ch_scr": 1,    "ch_tcp": 1}    → GetConfig {"ch_scr": 1,     "ch_tcp": 1}
SetConfig {"cue_mode": 1}                  → GetConfig {"cue_mode": false}
SetConfig {"cue_mode": true}               → GetConfig {"cue_mode": true}
```

### 波次 2：目录扫描时序与曲目缓存（WAV+CUE 主路径）

**现象**

- 载入 WAV+CUE 后只出现整轨 WAV；刷新页面/重新进入专辑也不恢复分轨。

**根因**

- `GetPlaylist` 返回后 aplayer **异步扫描**目录：`State.Scanning=true` 期间 `GetAlbums` 为空或仍是旧列表，`GetSongs` 可能是尚未分轨的整轨结果。
- APUI 1.0.0 固定 `sleep(600)` 后直接 `GetAlbums`，并把第一次 `GetSongs` 结果永久缓存；扫描结束后不刷新。
- 厂商 UI 的 `ParseState()` 会轮询 `State.Scanning`，扫描结束后才 `GetAlbums`。

**修复**

`web/src/store/index.ts`

- 新增 `waitForScan()`：`GetPlaylist` 后先读一次 `State`，`Scanning=true` 时每 250ms 轮询，结束后再取专辑（上限 60s）。
- `fetchAlbumsAfterScan()`：扫描结束后 `GetAlbums`；空结果延迟 350ms 重试一次。
- `fetchSongs()`：扫描中/扫描刚结束时等待并重读；空结果重试，避免缓存半成品。
- `handleScanComplete()`：轮询检测 `Scanning: true → false`，刷新专辑并清空曲目缓存，视图自动从整轨切换为 CUE 分轨。
- 专辑页增加兜底：只有一条 WAV 且名称含 CUE 或时长 >10 分钟、同时 `cue_mode=false` 时，显示“启用 .cue 并重新载入”按钮；保存后重新 `GetPlaylist` 触发扫描，并回到原专辑。

**本地证据**

```text
cue_mode=false, 赵聪 WAV+CUE → GetSongs: ["whole.wav"], 12000ms
cue_mode=true, 重新 GetPlaylist → GetSongs: 3 条 CUE 曲目（GBK 与 UTF-8 均通过）
目录扫描中 GetAlbums 为空；扫描结束后返回 CUE 曲目
APUI 请求序列：GetPlaylist → State(Scanning) → … → GetAlbums → GetSongs
```

### 波次 3：文件浏览载入错目录

**现象**

- 文件浏览中点击“赵聪”行“载入”，实际载入的是目录下第一个文件夹（李佳薇）。

**根因**

- 点击时复用渲染时的树索引；展开/折叠、首页自动载入或扫描会使索引失效。
- 扫描未完成时 `GetAlbums` 为空，旧代码回退到 `ensureLibrary()` 重新载入根目录，于是显示根目录第一张专辑。
- 首页自动载入与用户手动载入并发，可能互相覆盖。

**修复**

`web/src/store/index.ts` / `web/src/views/index.ts`

- `loadPlaylist` 点击时重新 `GetPlaylists&ind=-1`，按 `Drives[].path` 解析最新索引；播放列表文件按 `name`。
- 找不到/越界则提示刷新，不发送无效索引（本地实测越界索引可使 aplayer 进程退出）。
- 载入后等待扫描完成；空目录只显示空状态，不再回退根目录。
- `ensureLibrary` 与 `loadPlaylist` 共用串行队列，最后一次用户操作生效。
- `expandPlaylists` 同样按 path 重新解析。

**本地证据**

```text
根目录 /media 展开 → 载入 赵聪
结果：GetPlaylist&playlist=3 → 1 张专辑（赵聪）→ 3 条 CUE 曲目
未出现李佳薇目录
```

### 波次 4：电台“返回分类”与入口

**现象**

- 进入电台分类后，点顶部“返回分类”不返回。

**根因**

- `radioCategory` 是页面状态，返回按钮只修改 hash，没有清空分类；重绘后仍是分类详情。

**修复**

- `backButton` 支持可选 `onClick`；返回分类先 `setRadioCategory(null)` 再回 `#/radio`。
- 点击左侧/移动端“网络电台”入口时同样清空分类，回到分类列表。

**本地证据**

```text
进入分类 → 点击“返回分类” → “选择分类开始收听” + 45 个分类
进入分类 → 点击左侧“网络电台” → “选择分类开始收听” + 45 个分类
```

## 5. 风险与边界

- 本轮不修改 aplayer 音频引擎、不新增服务/端口。
- `cue_mode` 一旦已为 `false`，不自动全局改写；专辑页提供一次性“启用并重新载入”，也可在设置中手动开启。
- 目录扫描上限 60s；超大曲库若超过上限仍可能取到空/旧列表，但重试与扫描结束刷新会兜底。
- 真机测试避免改动 Scream 实际开关；Scream 的写入类型已在本机 aplayer 2.19 上实测验证。
